Building Confidence in Computational Physics

Verification vs. Validation: A Crucial Distinction

In computational science, "correctness" has two distinct meanings, captured by the terms Verification and Validation (V&V). It is one of the most important and often misunderstood topics in the field.

  • Verification: "Are we solving the equations right?" This is a purely mathematical exercise. It's the process of ensuring that the computer code you've written is a faithful and accurate implementation of the mathematical model you intended to solve. It checks for bugs, numerical errors, and convergence.
  • Validation: "Are we solving the right equations?" This is a scientific exercise. It's the process of determining how well your mathematical model (and your verified code) represents the real-world physics you are trying to simulate. This involves comparing the code's output to real experimental data.

A code can be perfectly verified but fail validation. This means your code flawlessly solves the equations, but those equations themselves are an incomplete or incorrect description of reality. This simulation lets you explore both processes.

Guide: Verification Mode

In this mode, we test our code against a known **analytical solution** to the 1D heat equation. This is a perfect mathematical truth, so any deviation is due to error in our numerical code.

  1. Select "Verification" from the Mode dropdown. The main chart shows the numerical solution from our code and the exact analytical solution.
  2. Use the **Grid Points** slider to change the resolution of the simulation. Notice how the numerical solution gets closer to the analytical solution as the number of points increases.
  3. Click **"Run Convergence Test"**. This will run the simulation at several different resolutions and plot the error between the numerical and analytical solutions on the bottom chart. You should see that the error decreases as the grid spacing (dx) gets smaller. This is a **convergence test**, a cornerstone of code verification.

Guide: Validation Mode

Here, we assume our code is verified. We now test it against synthetic **"experimental data."**

  1. Select "Validation" from the Mode dropdown. The main chart now shows our code's prediction versus the experimental data points.
  2. Initially, the data should match the code well (with some random noise). This is a successful validation.
  3. Now, turn on the **"Include Hidden Physics in Experiment"** switch. This adds a systematic error to the experimental data, simulating a physical effect (like a small heat source) that was *not included in our mathematical model*.
  4. Notice that our code, even though it's perfectly verified, now fails to match the experiment. This is a **validation failure**. It tells us not that our code is wrong, but that our *model* of the physics is incomplete. This is how computational scientists discover the need for better physical theories.
